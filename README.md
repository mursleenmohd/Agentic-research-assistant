# Agentic Research Assistant

An Agentic AI Research Assistant built with **LangGraph, LangChain, Groq, MCP, FastAPI, and Streamlit**.
The project demonstrates how an AI agent can plan a research task, ask for human approval, use MCP-based research tools, maintain workflow state, and synthesize research results into a final answer.

# Multi-Step AI Research Agent with LangGraph & MCP

An intelligent, stateful AI research assistant built using [LangGraph](https://www.langchain.com/blog/what-is-an-agent) and the [Model Context Protocol (MCP)](https://newsletter.systemdesign.one/p/how-to-build-an-ai-research-agent-with-mcp). The system leverages an LLM planner to break down research topics, incorporates a human-in-the-loop validation step, and autonomously executes deep investigations through modular tools before synthesizing a final report.

---

## Features

### Intelligent Research Planning
The system utilizes a Large Language Model (LLM) to intelligently decompose a broad, user-provided research topic into a structured series of targeted research questions.

* **Example:**
  * **User Query:** *"What are AI agents?"*
  * **Generated Plan:**
    1. What are AI agents?
    2. How do AI agents work?
    3. What are common applications of AI agents?
    4. What are the limitations of AI agents?

### Human-in-the-Loop Approval
To ensure high accuracy and alignment, the workflow includes an interactive checkpoint. The agent pauses immediately after generating the research plan and waits for user intervention before consuming execution tokens.

```text
Research Plan:
1. What are AI agents?
2. How do AI agents work?
3. What are their applications?
4. What are their limitations?

[ Approve & Continue ]   [ Reject Research ]
```
*The state transitions and approval pauses are safely managed using LangGraph's native interrupt/resume persistence mechanisms.*

### MCP Tool Integration
The architecture implements the **Model Context Protocol (MCP)** to securely decouple the core orchestration graph from external research utilities. The client establishes communication with the MCP server to expose the following operations:
* `research_topic`: Initiates individual query execution routes.
* `get_research_summary`: Extracts consolidated insights from external knowledge bases.

---

## Multi-Step Agent Workflow

The control flow is modeled explicitly as a stateful graph where nodes represent operational steps and conditional edges evaluate runtime status.

```text
   START
     ↓
  Planner
     ↓
Human Approval
     ↓
┌───────────────┐
│               │ Reject
│    Approve    ├─────────> [ Rejected ] ──> END
│               │
     ↓
 Researcher
     ↓
 [ MCP Tools ]
     ↓
Synthesizer
     ↓
    END
```

---

## Agent State

A unified, thread-safe memory state is shared dynamically across all nodes in the LangGraph workflow. The schema tracks the following properties:

| State Key | Type | Description |
| :--- | :--- | :--- |
| `research_topic` | `str` | The original input query provided by the user. |
| `research_plan` | `List[str]` | The collection of distinct sub-questions generated by the planner. |
| `research_results` | `List[Dict]` | Raw data payloads retrieved via the MCP tools. |
| `current_step` | `str` | The active pointer tracking graph node execution. |
| `approval_status` | `str` | Represents the human verification choice (`approved` / `rejected`). |
| `final_answer` | `str` | The comprehensively synthesized markdown report. |
| `messages` | `List[Message]` | The conversational history log appended throughout the execution loop. |

---

## Key Features

* **Interrupt and Resume:** LangGraph interrupts the workflow at the human approval stage. The workflow can later be resumed using the same thread ID. This demonstrates a real human-in-the-loop agent pattern.
* **Error Handling:** The research workflow resiliently handles edge cases such as MCP connection failures, missing research tools, tool execution failures, unknown research topics, or human rejection. Instead of crashing, the system gracefully recovers to return a useful response.

## Installation

### 1. Clone the repository
```bash
git clone https://github.com/mursleenmohd/Agentic-research-assistant.gt
cd agentic-research-assistant
```

### 2. Create a virtual environment
```bash
# Windows
python -m venv myenv
myenv\Scripts\activate

# macOS/Linux
python3 -m venv myenv
source myenv/bin/activate
```

### 3. Install dependencies
```bash
pip install -r requirements.txt
```

## Running the Project

The application requires running both the backend and frontend simultaneously in separate terminals.

### Terminal 1 — Start FastAPI Backend
From the project root directory, run:
```bash
python -m uvicorn backend.main:app --reload
```
* **API Home:** `http://127.0.0.1:8000`
* **Interactive API Documentation:** `http://127.0.0.1:8000/docs`

### Terminal 2 — Start Streamlit Frontend
From the project root directory, run:
```bash
python -m streamlit run frontend/app.py
```
* Streamlit will automatically open your web browser to the application page (typically `http://localhost:8501`).

**Known Limitations**  
This is an **Agentic AI learning/portfolio project**, not a production-grade research platform. The most important limitation is that the current MCP server uses a **hard-coded knowledge source**. Therefore, the system does not currently perform live web research.

The MCP server contains predefined information for specific topics such as:
* Artificial Intelligence (AI)
* Machine Learning (ML)
* Large Language Models (LLMs)
* AI Agents
* LangGraph
* Model Context Protocol (MCP)

## Questions Where the Current System Can Fail

1. **Latest News**  
   * *Example:* "What are the latest AI developments today?"  
   * *Why:* The system does not have a live news search tool. Therefore, it cannot reliably provide current information.
2. **Real-Time Events**  
   * *Example:* "What happened in the AI industry this morning?"  
   * *Why:* The current MCP server has no real-time data source.
3. **Latest Technology Releases**  
   * *Example:* "What is the latest NVIDIA AI GPU released in 2026?"  
   * *Why:* The system cannot guarantee an accurate answer because it does not perform live web research.
4. **Unknown Technical Topics**  
   * *Example:* "Explain a newly released AI framework that is not present in the MCP knowledge source."  
   * *Why:* The MCP server may return: `No specific information was found...`. The final answer may therefore be incomplete.
5. **Topics Requiring External Sources**  
   * *Example:* "Compare today's stock prices of NVIDIA, AMD, and Intel."  
   * *Why:* The current system does not have financial market tools.
6. **Questions Requiring Deep Source Verification**  
   * *Example:* "Find five recent academic papers about AI agents, compare their results, and provide citations."  
   * *Why:* The current system does not have a research-paper search engine or citation retrieval system.
